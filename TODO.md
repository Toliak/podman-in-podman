- [x] `--userns` support: spike first, then decide.
  - Resolved (2026-11-23): spike run against real podman 6.0.2 on this non-SELinux host; full log at `/tmp/opencode/pinp/userns-spike.md`. Baseline (our 4-extent map) → L2 `echo hello` + `podman build` rc=0. `--userns=host` gives L1 the rootless identity map (no userns, no `100000` anchor) and `--userns=keep-id` gives a linear subid map with no `100000` anchor; both make `newuidmap: write to uid_map failed: Operation not permitted` / `Error: cannot set up namespace using "/usr/bin/newuidmap": exit status 1`. `--userns=auto` fails with `not enough unused IDs in user namespace`. Podman refuses `--userns` + `--uidmap` (`Error: --userns and --uidmap/--gidmap/--subuidname/--subgidname are mutually exclusive`), so option (b) is ruled out for every mode.
  - Decision = split policy: `--userns=keep-id` (both `=` and two-token forms) is **stripped** and pinp's own maps are injected unchanged — keep-id-*compatible*, not native keep-id; `host`/`auto`/`nomap`/`ns:`/`keep-id:uid=`/`auto:size=` stay **rejected** with a mode-specific reason + `PINP_PASSTHROUGH=1` hint. `FindUserns`/`StripUserns` live in `argv.go`; both wrappers mirror the behavior. `--userns=host` is rejected because it means *no userns*, the opposite of what pinp exists for — this narrows the original "host + keep-id only" scope on evidence.
  - Also added preflight WARN checks for an active `containers.conf userns=` (parsed at `config.go:21`, previously unchecked) and for `PODMAN_USERNS`; the spike found both are silently overridden by injected maps rather than being hard collisions. Pytest covers all modes; see `tests/test_userns.py`.
  - What we do now: `argv.go:83` lists `--userns` in `Conflicts()`, so **every** value (`host`, `keep-id`, `auto`, `nomap`, `ns:...`) aborts with `conflicting arguments already supplied: --userns` (`cmd/pinp-e/main.go:37`, `cmd/pinp-i/main.go:45`); `tests/test_pinp_e.py:111` covers `--userns=host`. `PINP_PASSTHROUGH=1` bypasses all injection, but the error does not say so.
  - Why a spike: `man podman-run:2328` — `--uidmap` is incompatible with `--userns`, and our 4-extent algorithm is all `--uidmap`. `man podman-run:2333-2356`: `host` maps host `$UID` → container UID `0` with **no userns** (so L1 has no subordinate-ID space and L2 cannot build a nested userns — the thing pinp exists for); `keep-id` maps host `$UID` → container `$UID` with all subuids linear. Our current map (`idmap.go:57`) is already keep-id-like: `1002:0:1` puts the host user at container UID 1002 and container root ← first subuid 231072. Emulating `host` is just `1002:0:1` → `0:0:1`, but that is not the same as a real `--userns=host`.

Scope: `host` + `keep-id` only; `auto`/`nomap`/`ns:` stay rejected with a clearer error + `PINP_PASSTHROUGH=1` hint.
